# 00 進め方と考え方

作成: 2026-10-25

## 目的
この PC の Beads（`bd`）を最新版に上げ、各リポジトリの `.beads` を新しい版で使える状態にする。
進行中のプロジェクトがあるため、**issue の情報を失わないこと**を最優先にする。

## 原則
- 変更を加える前に必ずバックアップを取り、戻し方を決めておく。
- 移行の前後で同じ指標（issue 件数、未完了件数など）を取り、一致を確かめる。
- いきなり全件にかけず、影響の小さいリポジトリで試してから広げる。
- 1 件ずつ実行し、結果をこのリポジトリに記録する。

## ステップ
| # | ステップ | 内容 |
|---|---|---|
| 0 | 記録の場所と書式 | このリポジトリに手順書、スクリプト、実行ログを置く |
| 1 | 現状と最新版の把握 | 現在の版、入手方法、最新版、リリースノート（保存形式・スキーマの変更）を確認する |
| 2 | 対象の検索と棚卸し | `.beads` の場所に加え、issue 件数、未完了件数、git の状態（JSONL が commit 済みか）、git hooks の有無を一覧にする。移行後の比較基準になる |
| 3 | 方式の検討 | 本体の更新方法、各リポジトリの移行コマンド、ロールバック手順を決める |
| 3.5 | バックアップ | 全 `.beads` を別の場所へ丸ごとコピーし、ハッシュを記録する。旧版の `bd.exe` も退避する |
| 4a | 試験移行 | 影響の小さい 1〜2 件（例: `sql_viz_202604_old`）で試す |
| 4b | 本番移行 | 1 件ずつ実行し記録する。始める前に bd daemon が動いていないか確かめる |
| 5 | 検証 | 件数と未完了 issue が棚卸しと一致するか、`bd ready` / `bd list` が動くか、hooks が新しい版を呼ぶかを確かめる |
